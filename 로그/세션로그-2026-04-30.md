## 부록: `employment_types` 반복 요청·로컬 GET 에러 (2026-04-30)

인력 관리 화면에서 Supabase `employment_types` REST 가 과도하게 호출되던 문제는 (1) **`emplTypes` 변경마다 시드 mutation** + **mutation 후 무조건 무효화** 로 생기는 **invalidate ↔ refetch 루프**, (2) `useEffect` 의존성에 **`ensureTypes`(mutation 객체 전체)** 를 넣어 **매 렌더마다 effect 실행** → mutation 안의 `fetchTypes`(GET) 만으로도 무한 호출되는 경우가 겹쳐 있었다. 로컬에서 REST URL만 브라우저로 열 때는 JWT 가 없어 **401** 등이 날 수 있다(앱 내 호출과 다름).

증상·원인 표·수정 파일·재발 확인 순서의 **전체 정리는 [[에러로그-2026-04-30]]** 에 따로 적어 두었다.

## Phase 2 — 인증 구현 가이드 (계획 문서 반영)

체크리스트 `체크리스트.md` Phase 2 항목과 현재 코드베이스(`src/App.tsx`는 라우팅·보호 라우트, `src/lib/supabase.ts`는 클라이언트)를 기준으로 정리한 내용입니다. HTML 프로토타입(`gelato-management-prototype-v1.5.html`)은 로그인 UI가 없으므로, Shadcn 폼 패턴으로 새로 만드는 것이 맞습니다.

### 1. Supabase 대시보드 — 이메일/비밀번호

- **Authentication → Providers → Email**: 활성화.
- **Confirm email**: 로컬 개발에서는 끄거나, 켠 경우 회원가입 후 확인 메일 플로우를 알고 테스트할 것.
- **Authentication → URL Configuration**:
  - Site URL: 로컬은 `http://localhost:5173`, Vercel 배포 URL도 추가.
  - Redirect URLs에 동일하게 허용 목록 등록 (OAuth·매직링크 확장 시 필요).

### 2. DB — `stores` INSERT 가능 여부 확인 (중요)

설계 예시(`설계-2026-04-27.md`)는 `stores`에 `USING (owner_id = auth.uid())`만 있을 수 있다. **RLS가 켜진 상태에서 클라이언트가 `INSERT INTO stores`를 하려면**, PostgreSQL 규칙상 **`FOR INSERT` 정책 + `WITH CHECK (owner_id = auth.uid())`** 가 있어야 한다. 이미 넣었다면 스킵하고, 없다면 SQL Editor에서 추가한다.

```sql
CREATE POLICY "store insert own row"
ON stores FOR INSERT
WITH CHECK (owner_id = auth.uid());
```

이후 앱에서 `supabase.from('stores').insert({ owner_id: user.id, name: '...' })`가 거부되지 않는지 한 번 확인한다.

### 3. 프론트 의존성·라우팅

- **`react-router-dom`**: 인증 후 이동할 보호 라우트(`/`)와 공개 라우트(`/login`, `/signup` 또는 단일 `/auth`)를 나누기 위해 사용.
- `src/main.tsx`의 `QueryClientProvider` **안쪽**에 `BrowserRouter`를 두는 패턴이 일반적이다.

### 4. 세션 구독과 인증 상태

- **`supabase.auth.getSession()`** 초기 로드 + **`supabase.auth.onAuthStateChange`** 로 로그인/로그아웃 반영.
- 구현 방식 (택1이면 충분): **Context + Provider** (`AuthProvider`), 또는 **TanStack Query**로 세션 캐시.
- 목표: 로그인 여부·`user.id`를 한 곳에서 읽고, Phase 3 이후 `store_id` 조회에 재사용한다.

### 5. 로그인 / 회원가입 페이지

- **`signUp`**: `supabase.auth.signUp({ email, password })` — 필요 시 `options.data`에 표시명 등 메타데이터 (선택).
- **`signInWithPassword`**: `supabase.auth.signInWithPassword({ email, password })`.
- Shadcn `button` + 필요 시 `Input`, `Label`, `Card` 등으로 폼 구성.
- 에러 메시지는 Supabase `error.message`를 사용자에게 표시한다.

### 6. 로그인 후 `stores` 자동 생성 (체크리스트 핵심)

**의도**: 최초 인증 직후, 해당 사용자의 매장 레코드가 없으면 한 행 삽입.

권장 순서 (세션 확정 후 한 번 실행):

1. `select id from stores where owner_id = user.id` (limit 1).
2. 없으면 `insert({ owner_id: user.id, name: '기본 매장명' })` — 이름은 나중에 설정 화면에서 바꿀 수 있게 처리.

실행 위치 후보: 로그인/회원가입 성공 직후, 또는 보호된 레이아웃 마운트 시 `ensureStore()` (탭 여러 개에서 중복 INSERT 방지를 위해 DB에서 다시 `select` 후 없을 때만 insert).

### 7. 비로그인 시 리다이렉트

- **Protected route**: 세션 있을 때만 `children` 렌더.
- 세션 없음 + 초기 로딩 완료 시 **`Navigate` to `/login`**.
- 이미 로그인한 사용자가 `/login` 접근 시 `/`으로 리다이렉트하면 UX가 좋다.
- 세션 복원 중에는 짧은 로딩 스피너/스켈레톤으로 깜빡임을 줄인다.

### 8. 데이터 흐름 (요약)

- 공개: `/login`, `/signup` → `signIn` / `signUp` → Session → `ensureStore` → 없으면 `stores` insert → 보호된 `/`에서 이후 CRUD는 RLS로 `store_id` 스코프.

### 9. 완료 기준 (체크리스트와 매칭)

| 항목 | 확인 방법 |
|------|-----------|
| 이메일/PW 로그인 활성화 | 대시보드 Provider + 실제 로그인 성공 |
| 로그인/회원가입 페이지 | 브라우저에서 두 플로우 동작 |
| 매장 자동 생성 | 새 계정 또는 기존 계정에서 `stores`에 본인 `owner_id` 행 존재 |
| 비로그인 리다이렉트 | 시크릿 창에서 `/` 접근 시 로그인으로 이동 |

### 10. 다음 Phase와의 연결

Phase 3부터는 **`store_id`** 가 필요하다. Phase 2 마무리 시 **`useStore()`** 또는 `storeId`를 반환하는 훅으로 `ensureStore` 결과의 `id`를 캐시해 두면 이후 쿼리에 바로 넘길 수 있다.

**목적**: 월간 근무표와 주간·프로필 연동이 헷갈리는 문제를 줄이고, 단일 소스(주간 저장 슬롯 + 프로필 기본 요일)로 정렬.

1. **월간 근무표 UI** — 탭·패널 **숨김**(재도입 가능; DB·훅 유지).
2. **주간 근무표** — 버튼명 **«근무표 가져오기»**: `staff_default_shifts`(근무요일·시프트) + **근무관리–시프트 시간**으로 `useApplyWeekFromProfileDefaults` 일괄 적용.
3. **직원 프로필 · 근무 달력** — **주간 슬롯 저장분** 읽기 전용; 셀은 **「근무」**만 표시, 오픈/미들/마감 라벨 없음, **호버·클릭 모달**로 시간대 상세(`useStaffWeekCalendarPlans`, `plannedFromWeek`).
4. **주간 저장** — `window.confirm`: 저장 시 **출퇴근 예정·기준 데이터**와 연동한다는 문구.
5. **출퇴근 탭** — `gelato-management-prototype-v1.5.html` 스타일(날짜 그룹·직원 카드·예정/실제 2행); **예정** = 연관 주의 `fetchWeekSlots` → `mergePlannedByStaffDate` (시프트 설정 반영).
6. **구현 메모** — `src/lib/plannedFromWeek.ts`, `useStaffWeekPlan.ts`, `StaffPage.tsx` (`StaffAttendanceSection`, `StaffDetailForm`, `StaffScheduleSection`); 주간 그리드 **열 드래그**용 `onWeekCellMouseEnter` 복구.

## (이전) 근무표 UX 고도화 (2026-04-30 추가, 일부 구조 개편으로 대체)

*구조 개편(위 절) 이전 기록. 월간 탭·「월간에서 가져오기」 흐름은 UI·체크리스트에서 갱신됨.*

- **`StaffPage.tsx` 근무표**: 서브탭 **주간 | 월간 | 근무관리**. 주간은 **시작일 ~ 종료일** 가운데 정렬, «근무자 선택»+셀렉트 나란히, **저장**으로 `persistWeekDraft` 반영. **«월간 근무표 데이터 가져오기»** 한 버튼으로 `useReplaceWeekFromMonthWithSettings`(근무관리 시간대 → 슬롯) 후 **`useGenerateAttendanceBaseline`**.
- **주간 드래그**: v1.5와 같이 **같은 요일(열)** 안에서만 mousedown + mouseenter로 연속 슬롯에 선택 직원 배정.
- **월간**: 월요일 시작 **7열 달력**, 날짜 칸에 근무자 칩, 호버 시 시프트·근무관리 시간 안내, 클릭 시 일별 모달에서 편집; **`오늘 이전` 날짜는 편집 불가**; 상단 **저장**으로 `usePersistMonthScheduleDraft`(직원×일 전량 동기).
- **`useMonthCellsDateRange`**, 쿼리 무효화에 **`monthScheduleRange`** 포함해 주간 칩 색·월간 데이터 일치.
- **`useAttendance.ts`** — `generateAttendanceBaselineForWeek` 함수 분리 export (훅은 동일 동작).
