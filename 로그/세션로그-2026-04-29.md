## 추가 반영 (2026-04-29 이후 갱신) — 인력·근무표 UX

- **직원 목록 테이블**: 열을 `이름 / 연락처 / 고용형태 / 근무요일 / 급여` 로 변경. 고용형태는 매니저·직원·아르바이트 + **형태 등록**으로 확장. 근무요일은 요일 + 오픈·미들·마감 다줄 표기(`workRules`).
- **직원 상세**: 이름 클릭 또는 **+ 직원 등록** 시 동일 폼. 필드: 이름·연락처·사진·이력서·보건증 파일·보건증 만료일·고용형태·고용일·근무 기간(자동)·근무요일 편집·**월 달력**에서 일별 근무 형태 순환 입력.
- **근무표 탭**: (1) **주간** — 시간대를 **세로**로 두고 요일별로 근무자 `<select>` 배정. (2) **월간** — 직원 × 일자별 오픈/미들/마감 `<select>`.
- **설계 문서** `설계-2026-04-27.md`: `employment_types`, `staff` 확장 컬럼, `staff_default_shifts`, `staff_calendar_assignments`, `schedule_week_slots`, `schedule_month_cells` 및 프로토타입 매핑 표 추가.
- **Escape**: 직원 상세 열린 상태에서 `Esc` 시 상세 닫기(모바일 내비보다 우선).

- **샘플 데이터 보강** (`gelato-management-prototype-v1.1.html`): 고용형태 «인턴» 1건, 직원별 이력서·보건증 파일명·`calendar['2026-04']` 일부 일자, 주간 `WEEK_GRID` 다수 슬롯, 월간 `MONTH_SHIFT`는 달력 값 우선·없는 일은 요일 패턴, 출퇴근 `ATT_HISTORY` 추가 행, 급여 화면 당일 매출 샘플 `428000`, 3월 `WORK_MONTH` 2건. (`seedMonthShiftDemo`를 `STAFF` 선언 이후로 이동해 초기화 오류 방지.)

## v1.3 반영 사항 (2026-04-29 추가)

신규 파일: `gelato-management-prototype-v1.3.html`  
v1.2 기반에서 아래 6가지 기능을 구현하고, 예정 vs 실제 근무 설계를 보충함.

### 1. 인력관리 — 근무표

#### 1-1) 주간 근무표: 과거 시간대 잠금
- `isWeekCellPast(d, s)` 함수로 현재 시각보다 이른 슬롯(날짜+시간) 판별.
- 과거 셀: `class="wk-cell past"` 적용 → 회색 배경·`cursor:not-allowed`. 마우스다운·터치 이벤트 핸들러 삽입 안 함.
- 드래그 시도 시 조건으로 차단.

#### 1-2) 주간 근무표: 단건(셀 내 ×) 삭제
- 기존 «지우기» 선택 시 `WEEK_GRID[k]=[]` (전체 삭제) → **[변경]** 이름 chip 옆 `×` 버튼(`week-chip-del`)으로 단건 삭제.
- `removeWeekChip(event, d, s, staffId)`: 해당 `staffId`만 배열에서 제거.
- «배정 삭제» 모드에서 클릭 시 alert 안내("× 버튼 사용").
- 과거 셀의 chip에는 × 버튼 미표시.

#### 1-3) 월간 근무표: "월별 기본 근무 세팅" 버튼
- `applyMonthDefaultSchedule()`: 각 직원의 `workRules[{dow, shift}]`를 순회해 해당 월 전체 요일에 매핑.
- 이미 있는 수동 편집 데이터는 덮어씌워짐(confirm 후 적용 안내).
- `MONTH_SHIFT` + `staff.calendar[ym][day]` 양방향 갱신 후 `renderMonthShiftTable()` 호출.

#### 1-4) 월간→주간 연동: 칩 색상
- `chipShiftClass(staffId, d)`: `WEEK_DATES[d]`로 날짜를 추론 → `MONTH_SHIFT` 조회 → 오픈=초록/미들=파랑/마감=주황 클래스 반환.
- `renderWeekVerticalGrid()` 및 `updateWeekCell()` 호출 시 chip에 색상 적용.
- 월간 기본 세팅 후 주간 근무표 재렌더 시 색상 자동 반영.

#### 1-5) 주간 근무표→출퇴근 기준 데이터 생성
- 「📋 출퇴근 기준 데이터 생성」 버튼 추가 (주간 근무표 카드 우측).
- `generateAttBaseline()`: 슬롯별 직원 목록을 순회 → 첫 슬롯=출근, 마지막 슬롯+1시간=퇴근, 슬롯 수=근무시간으로 `ATT_HISTORY`에 삽입 (`_baseline:true` 태깅).
- 이미 해당 날짜·직원 기록이 있으면 스킵.

---

### 2. 예정 스케줄 vs 실제 근무 — 설계 보충 및 부분 구현

#### 2-1) 출퇴근 탭: 이전/오늘 데이터만 표시
- `renderTA()` 수정: `ATT_HISTORY.filter(a => a.date < today)` → 미래 날짜(기준 데이터 등) 제외.
- 이전 기록 최대 10건 역순 표시. 기준 데이터(`_baseline`) 배지 구분.

#### 2-2) 급여 및 정산: 서브탭 추가
- **서브탭**: `정산 조건` / `근무 시간` (`.payroll-subtabs`, `payrollSubTab()`)
- **2-2-1) 정산 조건 탭**: 기본급 기준을 «근무 시간» 탭의 실출퇴근 합산(`actualHoursForStaff()`)으로 변경.
  - `payrollForStaff()` 개선: 실근무 있으면 `ATT_HISTORY` 합산 우선, 없으면 `WORK_MONTH` fallback.
  - `pr-actual-hours` 행 추가로 기본급 산출 근거 시각화.
- **2-2-2) 근무 시간 탭**: 조회 월·직원 필터 설정, `renderWorkhoursTab()` 구현.
  - 상세 테이블: 직원·날짜·예정 시프트·실제 출근·퇴근·실근무h.
  - 요약 테이블: 직원별 출퇴근 건수·실근무 합계·기본급 산출.
- **2-2-3) 예정 vs 실제 비교**: `getPlannedTimesForDate(staffId, dateStr)`로 WEEK_GRID에서 예정 시간 조회 → `diffMinutes()` 비교.
  - 5분 초과 지각: 🔴 `diff-late`, 5분 초과 조퇴: 🔵 `diff-late`, 정상: ✅ `diff-ok`, 근무표 미배정: 안내 텍스트.
  - stat 박스에 «이번 달 실근무합» 추가.
