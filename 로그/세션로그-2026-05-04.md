> 체크리스트 Phase 8 후속 / Phase 9 연동 준비

**요구사항**  
- 출퇴근 탭에 **«출근»·«퇴근»** 버튼 추가.

- 추후 교체 예정: 지금은 인증 없이 수정 가능. OTP(카카오워크/Twilio) 연동 후 관리자 인증 게이팅 추가 예정.

## v1.8 — 출퇴근 기록 UI를 표(table) 형식으로 개편

### 요구사항

- 카드 그리드(`PersonBlock`) → 표 형식으로 통일.
- 전체 근무자 모두 매 날짜에 한 행으로 표시.
- 컬럼: **근무자 / 근태 / 출근예정 / 출근 / 출근상태 / 퇴근예정 / 퇴근 / 퇴근상태 / 근무시간** + 액션(출근·퇴근·수정 버튼).
- 근태 예정: `출근예정 / 휴무 / 연차` 중 택1.
- 출근 상태: `조기출근 / 정상 / 지각` 중 택1
  - `actual − planned ≤ -20분` → 조기출근
  - `-20분 < diff ≤ 0분` → 정상
  - `diff ≥ +1분` → 지각
- 퇴근 상태: `조퇴 / 정상 / 연장근무` 중 택1
  - `actual − planned ≤ -1분` → 조퇴
  - `0 ≤ diff < +20분` → 정상
  - `diff ≥ +20분` → 연장근무
- 근무시간: `실제출근 ~ 실제퇴근` 의 `h:mm` (둘 다 있을 때만).

### 구현

`src/pages/StaffPage.tsx`

- 신규: `PersonRow`, `AttendanceTableHead` 컴포넌트.
- 신규 헬퍼: `hmToMin`, `isoLocalMin`, `checkInStatus`, `checkOutStatus`, `workDurationLabel`, `attendanceLabelClass`.
- 기존 `PersonBlock` 카드 컴포넌트 제거(312줄). 사용하지 않게 된 헬퍼 (`isoToHm`, import: `diffPlannedVsActualCheckIn`)와 `mergeStaffIdsForDate`/`singleDayGroups` 도 정리.
- `StaffAttendanceSection` 의 「오늘」 / 「선택한 날짜」 / 「이전 기록」 세 영역 모두 `<table>` 로 렌더. 모바일 가로 스크롤은 `overflow-x-auto + min-w-[860px]`.
- 행 액션 셀: 출근·퇴근·수정 버튼을 컴팩트 사이즈(`h-6 px-2 text-xs`) 로 우측 정렬. 수정 모드는 같은 `<tr>` 아래 `<tr colSpan=10>` 인라인 편집 행으로 표시.

- 「연차」 라벨은 요구사항에 포함되어 있으나 현재 DB/스키마에 휴가·연차 테이블이 없음 → `plannedStatus` 는 잠정적으로 `예정 슬롯 유무` 만으로 「출근예정 / 휴무」 판정. 「연차」 분기는 추후 `staff_leaves` (가칭) 도입 시 추가.

## v1.11 — 출퇴근 기준 «N건 반영» 정합성 (집계·동기화)

### 원인

- `generateAttendanceBaselineForWeek` 가 **INSERT된 행만** 세어 `number` 로 반환 → 이미 해당일 `attendance` 가 있으면 전부 스킵되어 **0건**이 자주 나옴(실제로는 «생략·유지»가 대부분인데 메시지가 신규만 가리킴).
- **자동 기준(`is_baseline`·비수정)만** 있는 경우에도 주간표를 바꿔 저장해도 **UPDATE 없이 스킵**되어, DB 예정 시각이 새 슬롯과 어긋날 수 있음.
- 직원×일 맵 키를 `staff_id + '_' + day` 로 쓰던 부분은 UUID에 `_` 가 없어 당장은 문제 없었으나, **`|` 구분자**로 명확히 변경.

### 변경 (`src/hooks/useAttendance.ts`)

- 반환 타입을 **`GenerateBaselineSummary`** 로 교체: `plannedStaffDays`, `inserted`, `updated`, `skippedConflict`, `unchanged`.
- 당일 구간 조회는 **`maybeSingle` 제거** → 해당일 전부 `select` 후 분기(다중 baseline·실기록 공존 대비).
- **실제 출근(`!is_baseline`) 또는 `manually_corrected`** 가 있으면 그 직원·일은 건드리지 않음(`skippedConflict`).
- **자동 기준만** 있으면: 예정 시각이 같고 중복 없으면 `unchanged`, 아니면 **대표 1행 `UPDATE` + 나머지 baseline 중복은 `DELETE`** 로 `updated` 반영.
- `describeBaselineSyncSummary()` 로 저장 완료 알림 문구를 **한 줄 요약**(신규·수정·동일·유지)으로 생성.

### UI (`src/pages/StaffPage.tsx`)

- 저장 성공 알림: `출퇴근 기준 N건 반영` 단일 숫자 제거 → **`describeBaselineSyncSummary(summary)`** 본문 사용.

### 기타

- `useGenerateAttendanceBaseline` 성공 시 출퇴근 쿼리 무효화를 **`['attendance']` + active** 로 `useCorrectAttendance` 와 맞춤.

## v1.12 — 주간 «근무표 가져오기» 전체 vs 선택 직원

### 동작

- **근무자 선택 «전체»** (`pickStaff === ''`): `weekDraftFromProfileDefaults(전체 직원)` 만으로 **그리드 초안 전량 교체**(기존과 같이 전체 리셋 후 전 직원 프로필 근무요일·시프트 반영). 확인 문구·완료 알림에 «전체 초기화」 명시.
- **특정 근무자 선택 시**: `stripStaffFromWeekDraft` 로 해당 `staff_id` 만 모든 슬롯에서 제거한 뒤, `mergeWeekDraftWithProfileForStaff` 로 **그 직원 한 명**의 `staff_default_shifts` 만 `weekDraftFromProfileDefaults` 에 넣어 병합 — **다른 직원 칩은 유지**. 프로필에 근무 규칙이 없으면 해당 인원만 제거하고 알림으로 안내.

### 코드

- **`src/hooks/useWeekSchedule.ts`**: `ProfileStaffRow` export, `stripStaffFromWeekDraft`, `mergeWeekDraftWithProfileForStaff` 추가.
- **`src/pages/StaffPage.tsx`**: «근무표 가져오기» `onClick` 분기·`confirm`/`alert` 문구, 주간 카드 `CardDescription` 갱신.
