## 추가 세션 — 직원·알바 급여 모드 분리 기획

### 배경

기획상 staff 종류에 따라 급여 정산·출퇴근 로직이 달라져야 함:

- **직원(+매니저)**: 시급×시간 아닌 **기본급 + 상여금** 지급, **월 8회 휴무** 적용
- **알바**: 기존 시급×실근무시간
- **공통**: 근무표·급여정산 화면은 통합해서 보여줌 (시프트 코드는 동일, 내부 해석만 다름)

추가로, 오픈·미들·마감의 기본 시간은 **직원 근무 기준 = 매장 기본값**으로 두되, 알바생은 **개인별 시프트 시간 오버라이드**가 가능해야 함.

### 결정 사항

| 항목 | 결정 |
|---|---|
| 직원 상여금 | 매월 다름 → `payroll.bonus` 행에 입력 (staff 컬럼 X) |
| 월 8회 휴무 미달/초과 | 표시·경고만, 자동 감액 없음 (사장 수동 조정) |

### DB 마이그레이션 계획 (`feature5_pay_mode.sql`)

```sql
-- 1. employment_types: 급여 모드 플래그
ALTER TABLE employment_types
  ADD COLUMN pay_mode text NOT NULL DEFAULT 'hourly'
    CHECK (pay_mode IN ('hourly','salary')),
  ADD COLUMN monthly_off_days int;  -- salary일 때만 의미

-- 2. staff: 직원 전용 기본급
ALTER TABLE staff ADD COLUMN base_salary numeric;

-- 3. staff_shift_overrides: 알바 개인별 시프트 시간
CREATE TABLE staff_shift_overrides (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  store_id uuid NOT NULL REFERENCES stores(id) ON DELETE CASCADE,
  staff_id uuid NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  shift text NOT NULL CHECK (shift IN ('open','middle','close')),
  start_slot_index int NOT NULL,
  end_slot_index int NOT NULL,
  CHECK (end_slot_index > start_slot_index),
  UNIQUE (staff_id, shift)
);
-- + RLS 정책 (표준 store_id 패턴)

-- 4. payroll: 상여금·휴무 추적 + 산정 당시 모드 스냅샷
ALTER TABLE payroll
  ADD COLUMN pay_mode text CHECK (pay_mode IN ('hourly','salary')),
  ADD COLUMN bonus numeric DEFAULT 0,
  ADD COLUMN off_days_used int,
  ADD COLUMN off_days_required int,
  ADD COLUMN off_days_warning text;  -- 'shortage' | 'excess' | null
```

### 계산 로직 (`lib/payroll.ts`)

```ts
function calcPay(staff, type, attendance, period, manualBonus = 0) {
  if (type.pay_mode === 'salary') {
    const offDays = countOffDays(staff.id, period);
    const required = type.monthly_off_days ?? 8;
    return {
      pay_mode: 'salary',
      base_pay: staff.base_salary,
      bonus: manualBonus,
      allowances: 0,
      off_days_used: offDays,
      off_days_required: required,
      off_days_warning:
        offDays < required ? 'shortage' :
        offDays > required ? 'excess' : null,
      total: staff.base_salary + manualBonus,
    };
  } else {
    const hours = sumActualHours(staff.id, period);
    return {
      pay_mode: 'hourly',
      base_pay: staff.hourly_rate * hours,
      bonus: 0,
      allowances: calcHolidayPay(...) + calcNightPay(...),
      total: base_pay + allowances,
    };
  }
}
```

### 특이사항: 설계와 실제 코드 불일치 발견 + 조정

기존 SQL 컨벤션 확인 차 `feature3_store_shift_settings.sql`, `feature4_payroll.sql`을 읽다가 설계 문서(v1.3·v1.4)와 실제 DB 스키마 사이에 **시프트 시간 저장 방식이 다르다는 점**을 발견.

| 항목 | 설계 문서 (v1.3·v1.4) | 실제 코드 (`feature3_store_shift_settings.sql`) |
|---|---|---|
| 매장 시프트 시간 저장 | `store_shift_settings` 별도 테이블, `*_anchor_slot_index int` | `stores` 테이블에 `shift_open_start text` 등 6개 컬럼 (HH:MM) |
| 단위 | 슬롯 인덱스 (정수) | HH:MM 텍스트 |

→ **`staff_shift_overrides`도 실제 코드 컨벤션에 맞춰 HH:MM 텍스트로 작성**:

```sql
CREATE TABLE staff_shift_overrides (
  ...
  shift       text NOT NULL CHECK (shift IN ('open','middle','close')),
  start_time  text NOT NULL,                   -- HH:MM
  end_time    text NOT NULL,                   -- HH:MM
  ...
  CHECK (start_time ~ '^[0-2][0-9]:[0-5][0-9]$'),
  CHECK (end_time   ~ '^[0-2][0-9]:[0-5][0-9]$'),
  CHECK (end_time > start_time),
  UNIQUE (staff_id, shift)
);
```

### 부수 효과: 미결사항 #1 자동 해결

v1.4 §9 미결사항 #1 (매장 시프트 종료 슬롯 추가 여부)이 자연 소멸. `stores`에 이미 `shift_*_start`/`shift_*_end` 쌍이 있어서 종료 시간을 따로 추가할 필요가 없음.

### 헬퍼 시그니처도 조정 필요

설계 v1.4에 적은 `getShiftSlotsForStaff(...): { startSlot: number; endSlot: number }`는 슬롯 인덱스 기준이라 폐기. 실제 구현은:

```ts
export function getShiftTimeForStaff(
  staffId: string,
  shift: 'open' | 'middle' | 'close',
  store: Pick<Store, 'shift_open_start'|'shift_open_end'
                    |'shift_middle_start'|'shift_middle_end'
                    |'shift_close_start'|'shift_close_end'>,
  overrides: StaffShiftOverride[],
): { startTime: string; endTime: string }   // 'HH:MM'
```

## 임시 결정 — 직원 주휴수당 (미결사항 #2)

근로기준법 시나리오 정교화는 별도 검토가 필요하지만, `calcPay()` 구현이 막히지 않도록 **임시 정책**을 정함:

- **salary 모드**: `allowances = 0` (주휴수당 산정 스킵)
  - 통설: 월급제 기본급에 주휴수당이 포함되어 있다고 간주
  - 추후 정책 확정되면 `calcPay()` salary 분기에서 별도 항목 추가
- **hourly 모드**: 기존 설계대로 `calcHolidayPay(hours, hourly_rate)` 호출 (주 15h 이상 시 가산)

이 임시 결정은 설계 v1.4-r1 §11 체크리스트의 `calcPay()` 항목에 반영. 미결사항 #2는 여전히 열려있으며, 정책 결정 후 마이그레이션 없이 함수만 수정하면 됨.

## 추가 세션 — 설계 v1.4-r1 §11 체크리스트 2~4번 구현 (hooks·헬퍼)

### 1. `hooks/useEmploymentTypes.ts` 확장

기존 `EmploymentTypeRow`에 `pay_mode`, `monthly_off_days` 필드 반영.

**변경 사항**

```ts
export type PayMode = 'hourly' | 'salary'

export type EmploymentTypeRow = {
  id: string
  store_id: string
  code: string
  label: string
  pay_mode: PayMode          // 신규
  monthly_off_days: number | null   // 신규
}
```

- `mapRow`: `pay_mode` 화이트리스트 검증(`'salary'` 외엔 전부 `'hourly'`로 정규화), `monthly_off_days`는 null·undefined → null로 통일.
- `DEFAULT_EMPLOYMENT_SEEDS` 타입을 `EmploymentSeed[]`로 확장:
  - `manager` / `staff` → `salary` / 8일
  - `parttime` / `other` → `hourly` / null
- `fetchTypes` SELECT 컬럼에 `pay_mode, monthly_off_days` 추가.
- `useEnsureDefaultEmploymentTypes` INSERT 페이로드에 두 컬럼 포함 — 기본 시드가 처음부터 올바른 모드로 들어감.
- `useCreateEmploymentType` 시그니처 확장:
  ```ts
  mutationFn: async (input: {
    code: string
    label: string
    pay_mode?: PayMode              // 옵셔널, 기본 'hourly'
    monthly_off_days?: number | null
  }) => { ... }
  ```
  - `pay_mode === 'salary'`이면 `monthly_off_days` 기본 8, hourly면 강제 null.

### 2. `hooks/useStaffShiftOverrides.ts` 신규

`staff_shift_overrides` 테이블 CRUD. **`start_time`/`end_time`은 HH:MM 텍스트** (설계 v1.4-r1 §2.3).

**Export 목록**

| 심볼 | 역할 |
|---|---|
| `StaffShiftOverrideRow` 타입 | 행 모델 (`shift: ShiftCode`, `start_time`/`end_time: string`) |
| `useStaffShiftOverrides()` | **매장 전체** 오버라이드 조회 — `getShiftTimeForStaff` 헬퍼에 통째로 전달용 |
| `useStaffShiftOverridesFor(staffId)` | **단일 직원** 조회 — 프로필 폼·`ShiftOverridesEditor`용 |
| `useUpsertStaffShiftOverride()` | `onConflict: 'staff_id,shift'` UPSERT |
| `useDeleteStaffShiftOverride()` | «매장기본 사용»으로 되돌릴 때 행 삭제 |

**검증 로직** (`useUpsertStaffShiftOverride`)
- 클라이언트 측 HH:MM 정규식: `/^([01]\d|2[0-3]):[0-5]\d$/`
- `end_time <= start_time`이면 에러 throw — DB CHECK 도달 전 사용자 메시지로 차단.

**캐시 무효화 패턴**

`onSuccess`에서 두 키 모두 무효화:
```ts
queryClient.invalidateQueries({ queryKey: ['staffShiftOverrides', storeId] })
queryClient.invalidateQueries({ queryKey: ['staffShiftOverrides', storeId, v.staff_id] })
```
→ 매장 전체 쿼리와 직원별 쿼리가 동시에 살아있을 때도 동기화.

**`mapRow` 가드**: `shift` 값이 `'open'|'middle'|'close'` 아니면 `null` 반환 후 filter — DB CHECK가 있어도 클라이언트 타입 안정성 보강.

### 3. `lib/shiftResolver.ts` 신규

설계 v1.4-r1 §3 시그니처 그대로 구현. **이 한 함수가 근무표·출퇴근 baseline·급여 계산 전체에서 동일하게 호출**될 단일 진입점.

```ts
export function getShiftTimeForStaff(
  staffId: string,
  shift: ShiftCode,
  store: StoreShiftColumns,
  overrides: StaffShiftOverride[],
): ShiftTime
```

**우선순위 (3단계 폴백)**

1. `overrides`에서 `(staff_id, shift)` 매칭되는 행 → `{ startTime, endTime }`
2. `store.shift_${shift}_start` / `store.shift_${shift}_end` (인라인 컬럼)
3. `DEFAULT_SHIFT_TIME_SETTINGS[shift]` — `stores` 컬럼이 null일 때 최종 폴백 (설계 §3은 2단계지만 실제 `StoreRow`가 nullable이라 안전망 추가)

**타입 호환 처리**

- `StoreShiftColumns`는 `ensureStore.StoreRow`의 6개 컬럼만 `Pick`한 형태로 정의 (nullable 허용).
- `ShiftCode` 타입을 자체 export — `useStaff`의 동일 union과 호환 가능 (구조적 타이핑).

### 5. `lib/payroll.ts` 신규

5개 export, 전부 순수 함수:

| 함수 | 역할 |
|---|---|
| `sumActualMinutes(staffId, attendance, period)` | 기간 내 실근무 분 합계 (`is_baseline=false`, check_out 필수) |
| `sumActualHours(staffId, attendance, period)` | 위의 ÷60 |

**`calcPay` salary 분기**
```ts
{
  pay_mode: 'salary',
  base_pay: staff.base_salary ?? 0,
  bonus: manualBonus,
  allowances: 0,                          // 주휴 스킵 (임시 정책)
  off_days_used / required / warning,     // 휴무 미달/초과 경고
  total: base_pay + bonus,
}
```

**`calcPay` hourly 분기**
```ts
{
  pay_mode: 'hourly',
  base_pay: Math.round(workMinutes/60 * rate),
  bonus: 0,
  allowances: calcHolidayPay + calcNightPay,
  off_days_*: null,
  total: base_pay + allowances,
}
```

`type === null` → fallback hourly (안전망).
