#### Phase 2 — 일별 예외 시각 (①안)

**시각 우선순위 헬퍼** (`lib/shiftResolver.ts`)
```ts
export function getShiftTimeForDay(
  staffId, shift,
  cell: { start_time, end_time } | null,
  store, overrides,
): ShiftTime {
  if (cell?.start_time && cell?.end_time) return { ... cell }
  return getShiftTimeForStaff(staffId, shift, store, overrides)
}
```

**useMonthSchedule.ts 확장**
- `MonthCellRow`에 `start_time: string | null`, `end_time: string | null` 추가

- `useUpsertMonthCell`·`MonthDraftEntry`·`usePersistMonthScheduleDraft` 시그니처에 시각 추가

**Draft 모델 변경**
- 이전: `Record<string, ShiftCode | null>`
- 이후: `Record<string, MonthDraftCell>` where `MonthDraftCell = { shift, start_time, end_time } | null`

**월간 셀 UI — 시프트 모드 토글**

- 칩: 수동 시각 있으면 `이름  10:00~13:00`, 없으면 `이름  오픈`
- tooltip: `오픈 10:00~13:00 (당일 예외)` 표시 (`formatShiftTimeForCell` 헬퍼)

### 4. **staff_shift_overrides 자동 반영 차단** (v1.5.1)

**문제**: ShiftOverridesEditor에서 알바 시프트 시간을 바꾸면 → 근무표·출퇴근 baseline에 즉시 반영됨. 사용자 요구: 「기본 근무 세팅」 클릭 시점에만 적용.

**해결: 시각 결정 헬퍼에서 override 제거**

```ts
// 변경 전
getShiftTimeForDay(staffId, shift, cell, store, overrides):
  cell.start/end → staff_shift_overrides → store → DEFAULT

// 변경 후 (v1.5.1)
getShiftTimeForDay(shift, cell, store):
  cell.start/end → store → DEFAULT
```

- `staff_shift_overrides`는 더 이상 시각 결정에 자동 참여하지 않음
- override는 **`useApplyMonthDefaultFromProfiles` 시점**에만 적용 → cell INSERT 시 `start_time/end_time`에 명시 저장
- 이후 사용자가 override 변경해도 이미 저장된 cell은 영향받지 않음

**호출처 정리**
- `getShiftTimeForDay`: 3-arg 시그니처로 단순화
- `generateAttendanceBaselineForMonth`: `overrides` 인자 제거
- `useGenerateAttendanceBaselineForMonth`: `fetchOverridesForStore` 호출 제거
- 월간 셀 칩 시간 표시: `getShiftTimeForStaff` → `getShiftTimeForDay(shift, null, store)` 사용 (매장 기본 fallback)

**`useApplyMonthDefaultFromProfiles` 확장**
- 시작 시점에 `staff_shift_overrides` 매장 전체 fetch
- `(staff_id, shift)` 매핑으로 cell INSERT 페이로드에 `start_time/end_time` 명시 채움
- 이게 staff override가 의미를 갖는 유일한 경로

### 5. 월간 근무표 — 지난 날짜 lock

- `isPast = date < todayYmd` 판정
- `handleCellClick`: 지난 날짜면 alert `"지난 날짜는 수정할 수 없습니다"` + 차단
- 셀 스타일: `bg-muted/30 cursor-not-allowed opacity-60` (편집 모드에서만 회색)
- `isClickable`에 `!isPast` 조건 추가

### 6. 출퇴근 — 지난 날짜 수정·삭제 lock

`PersonRow`에 `isPast = dateKey < todayYmd`:
- 「수정」 버튼: `disabled` + `title="지난 날짜는 수정할 수 없습니다."`
- 인라인 행의 「저장」 / 「삭제」도 `disabled` (수정 모드 진입 후 보호)
- 출근/퇴근 punch는 `showPunch` flag로 오늘 행에만 표시되므로 추가 가드 불필요

### 2. 「저장」 — DB와 diff 비교, 변경점만 UPSERT

**문제**: 이전 `onSave`는 draft의 모든 키를 entries에 push → 31일 × 5명 = 155건 매번 UPSERT.

**해결**: `monthCells`(DB)와 `monthDraft`를 비교해 실제 변경된 entry만 추출.

```ts
const dbByKey = new Map(monthCells.map(c => [`${c.staff_id}|${c.work_date}`, c]))
const draftKeys = new Set(Object.keys(monthDraft))

for ([key, val] of monthDraft) {
  const db = dbByKey.get(key)
  if (val === null && db) → 삭제 entry
  else if (!db) → INSERT entry
  else if (db.shift !== val.shift || db.start_time !== val.start_time || db.end_time !== val.end_time) → UPDATE entry
  else → skip (변경 없음)
}

// DB엔 있지만 draft에 키 자체가 없는 경우 → 삭제 (휴무로 변경된 셀)
for (c of monthCells) {
  if (!draftKeys.has(key)) → 삭제 entry
}

if (entries.length === 0) {
  alert('변경된 내용이 없습니다.')
  return false  // 편집 모드 유지
}
```

**비교 항목**: `shift`, `start_time` (null 포함), `end_time` (null 포함) 3개. 하나라도 다르면 변경으로 판단.

**alert 메시지에 변경 건수 표시** — `"월간 근무표가 저장되었습니다. (변경 N건)\n..."` → 사용자가 실제 작업량 가시화.

## 추가 세션 — MY 페이지 (매장 정보 입력) (v1.5.8)

### 배경
명세서 헤더에 「회사명/사업자번호/대표자/주소/연락처」 표시 필요. 매장 정보를 입력·수정할 수 있는 페이지가 부재했음. 「설정」 카테고리 신설.

### DB 마이그레이션
`supabase/sql/feature6_store_info.sql` — `stores`에 4컬럼 추가:
```sql
ALTER TABLE stores ADD COLUMN IF NOT EXISTS business_no text;  -- 사업자등록번호
ALTER TABLE stores ADD COLUMN IF NOT EXISTS owner_name text;   -- 대표자명
ALTER TABLE stores ADD COLUMN IF NOT EXISTS address text;      -- 매장 주소
ALTER TABLE stores ADD COLUMN IF NOT EXISTS phone text;        -- 매장 연락처
```
RLS는 기존 `stores` 정책(`owner_id = auth.uid()`) 그대로 사용.

### 구현
- `src/lib/ensureStore.ts`: `StoreRow` 타입에 4필드 추가, select 컬럼 상수화(`STORE_SELECT_COLUMNS`)
- `src/hooks/useStore.ts`: `useUpdateStoreInfo` 뮤테이션 훅 신규, `['store']` 캐시 무효화
- `src/pages/MyPage.tsx` (신규): 5필드 폼 — 매장명(필수) + 대표자명 + 사업자번호(10자리 검증·자동 「-」 포매팅) + 연락처(02/지역/모바일 분기 포매팅) + 주소. 매장 ID 표시(기술 지원용 select-all 코드 블록)
- `src/App.tsx`: `/my` 라우트 등록
- `src/components/layout/AppLayout.tsx`: 「설정」 카테고리 + 「내 매장 정보」 NavLink + `IconStore` SVG + pageTitle 매핑
- `src/pages/PayrollPage.tsx`: `PayrollPrintSheet` 헤더에 매장 정보 그리드 추가 (값 있는 항목만 노출)
